# 辣条log · 部署运维手册

版本 v0.2 ｜ 2026-11-13

## 1. 本地运行（开发者）

```powershell
# 方式 A：IDEA 直接运行（推荐，.env 自动加载）
运行 AiTerminalApplication → http://localhost:8080

# 方式 B：启动脚本（自动打包）
.\start.ps1

# 方式 C：命令行
$env:OPENAI_API_KEY = "你的Key"
mvn spring-boot:run
```

配置文件 `.env`（本地，不入库）：
```
OPENAI_API_KEY=xxx          # 必填
OPENAI_MODEL=glm-5.3-flash  # 聊天模型
OPENAI_VISION_MODEL=glm-4.5v
OPENAI_IMAGE_MODEL=cogview-3-flash
```

## 2. Docker 部署

```powershell
docker compose up --build          # H2 单容器
docker compose --profile mysql up  # MySQL 持久化
```
compose 自动读取 `.env`。

## 3. 数据与备份

| 资产 | 位置 | 备份方式 |
|---|---|---|
| H2 数据库 | `data/ai-terminal.mv.db` | 停服后复制 data/ 目录 |
| 图片资产 | `data/uploads/` | 同上 |
| MySQL | 容器卷 | mysqldump 定时任务（规划） |

**升级发布**：替换 jar → 重启；`ddl-auto: update` 自动做轻量 schema 迁移（只增不改，风险低）。

## 4. 健康与日志

| 项 | 说明 |
|---|---|
| 健康检查 | `GET /actuator/health` → `{"status":"UP"}` |
| 应用日志 | 控制台（start.ps1 前台可见）；后台运行可重定向到 `data/app.log` |
| 关键日志点 | .env 加载条数、图片生成失败（含厂商 HTTP 码）、落库失败 |

## 5. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"尚未配置 API Key" | 环境变量/.env 缺失 | 检查 `.env` 或 Run Configuration |
| 401/403 | Key 无效或过期 | 智谱控制台重建 Key |
| 404 model not found | 模型名与厂商不匹配 | 核对 `OPENAI_MODEL` 等 |
| 405 / 路径错误 | base-url 与 completions-path 拼接不对 | 见 application.yml 注释 |
| 429 | 触发厂商限流 | 稍后重试 / 换模型 |
| 端口占用 8080 | 旧实例未停 | `Get-NetTCPConnection -LocalPort 8080` 找 PID kill |
