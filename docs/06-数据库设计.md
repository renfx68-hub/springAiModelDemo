# 辣条log · 数据库设计

版本 v0.2 ｜ 2026-11-13 ｜ 默认 H2 文件库（`data/ai-terminal.mv.db`），docker profile 切 MySQL

通用：Hibernate `ddl-auto: update` 按实体自动建表；表名/列名由实体注解固定，避免方言漂移。

## 1. 现有表 ✅

### chat_sessions（会话）
| 列 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(36) PK | UUID |
| title | VARCHAR(255) | 标题（首条消息自动命名） |
| created_at / updated_at | TIMESTAMP | 时间戳 |

### chat_messages（消息）
| 列 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AUTO | 自增 |
| session_id | VARCHAR(36) FK → chat_sessions | 删会话级联删消息 |
| role | VARCHAR(16) | `user` / `assistant` |
| content | CLOB | 文本内容（生成图片的助手消息为空串） |
| image_url | VARCHAR(100) | 图片引用 `/api/images/{uuid}.{ext}`，无图为 NULL |
| created_at | TIMESTAMP | 排序键（与 id 双重排序保证稳定） |

索引：`idx_message_session` (session_id, created_at, id)。

### 文件资产（非 DB）
`data/uploads/{uuid}.{ext}`：上传图与生成图统一落这里，DB 只存 URL。

## 2. 规划表 📋

| 表 | 迭代 | 关键列 |
|---|---|---|
| users | S6 账号体系 | id, email, password_hash, nickname, created_at |
| oauth_accounts | S6 | id, user_id→users, provider(google/wechat), provider_user_id, created_at |
| chat_sessions 加 user_id | S6 | 数据隔离 |
| attachments | S4 语音/附件 | id, session_id, kind(audio/file), path, size, mime |
| knowledge_docs | S5 知识库 | id, session_id?, filename, chunks, status |
| knowledge_chunks | S5 | id, doc_id, seq, text, embedding(向量) |

## 3. 运维要点

1. **备份**：冷备 `data/` 目录（H2 文件 + uploads）即可完整恢复；上 MySQL 后改用 mysqldump。
2. **迁移**：MySQL profile 首次启动 `ddl-auto: update` 自动建表；`schema.sql` 的 H2 专用语法在 MySQL profile 已禁用。
3. **清理**：暂无消息量上限；规划 S6 增加"单会话消息数 / 图片保留期"策略。
