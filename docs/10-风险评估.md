# 辣条log · 风险评估与应对

版本 v0.1 ｜ 2026-11-13 ｜ 概率/影响：高/中/低

| # | 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|---|
| 1 | 厂商 API 不稳定/限流（429、超时） | 中 | 高 | 错误可读化+可重试；模型可秒切（配置）；关键功能做超时上限 |
| 2 | 免费额度政策变化导致成本上升 | 中 | 中 | 厂商可替换是架构原则；监控用量；随时切换免费模型 |
| 3 | API Key 泄露 | 低 | 高 | .env 不入库；.gitignore 双保险；泄露即控制台重置 Key |
| 4 | 内容合规（生成图/文本违规） | 中 | 高 | 依赖厂商侧合规过滤；后续加敏感词前置过滤与举报入口 |
| 5 | 上传/生成图片滥用导致磁盘膨胀 | 中 | 中 | 单图 8MB 上限；规划保留期清理任务；上云后挂独立卷 |
| 6 | XSS/路径穿越等安全问题 | 低 | 高 | DOMPurify 净化；UUID 文件名+白名单正则；继续按清单审 |
| 7 | H2 单文件库损坏/误删 | 低 | 高 | data/ 目录定期备份；S6 切 MySQL |
| 8 | 人设梗影响回答准确性 | 中 | 中 | 「专业模式」开关；提示词约束"事实优先" |
| 9 | 范围蔓延（功能越做越多不发版） | 高 | 中 | PRD 优先级纪律；Sprint 验收即发版；新需求先入档 |
| 10 | 单人维护的巴士因子 | 高 | 中 | 文档齐全（本目录）；代码按功能小步提交；关键决策落文档 |

## 处置原则

1. **高风险项必须有对策且已落地**（1/3/6 当前已覆盖）。
2. 每迭代结束复查一次本表，新增风险随时补录。
3. 触发任何"影响/概率"升级的事故，事后补一条"事故复盘"到本文。
